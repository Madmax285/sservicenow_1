# Portfolio Demo Walkthrough

Use this sequence when presenting the project after the ServiceNow runtime is implemented.

## 1. Introduce the Problem

Explain that network requests involve repetitive validation, approval, fulfillment, communication, and tracking.

## 2. Show the Catalog Item

Demonstrate the Network Request form and its variables. Change the request type to show the dynamic Device behavior.

## 3. Submit a Request

Submit a realistic test request and show the resulting request record.

## 4. Show Automation

Open the Flow Designer automation and explain the validation, approval, rejection, fulfillment, and completion branches.

## 5. Show Approval

Demonstrate an approval request and the rejection/approval outcomes.

## 6. Show Fulfillment

Open the generated fulfillment task, demonstrate assignment, work notes, state progression, and completion.

## 7. Show Notifications

Show the relevant notification records or received messages.

## 8. Show Security

Explain requester, approver, engineer, and administrator access boundaries.

## 9. Show Reporting

Present request state, priority, workload, approval, and fulfillment visibility.

## 10. Close with Engineering Practices

Highlight separation of concerns, server-side validation, least privilege, testing, documentation, and Update Set deployment discipline.

Only demonstrate features that have actually been implemented and verified in the ServiceNow instance.
